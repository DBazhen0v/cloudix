# Сайт продажи серверов

Flask-сайт: каталог тарифов, регистрация и вход клиентов (email + пароль),
личный кабинет с заказом сервера и заявками на действия (перезагрузка,
продление, смена тарифа), админка для обработки подписок и заявок (SQLite).

## Запуск локально

```powershell
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt

python generate_admin_hash.py   # придумайте пароль, скопируйте хэш
copy .env.example .env          # впишите SECRET_KEY и ADMIN_PASSWORD_HASH

python run.py
```

Откройте http://127.0.0.1:5000 — каталог тарифов и форма заявки.
Админка: http://127.0.0.1:5000/admin/login.

`SECRET_KEY` — любая длинная случайная строка (например,
`python -c "import secrets; print(secrets.token_hex(32))"`).

## Что редактировать под себя

- Тарифы, цены и категории (сейчас: серверы для ботов/скриптов,
  веб-хостинг, Minecraft-сервера) — таблица `plans` в `app/db.py`
  (переменная `SEED_PLANS`, первое поле — категория), либо руками в
  файле `instance/shop.sqlite3`. Можно добавить несколько тарифов в
  одну категорию — на главной они сгруппируются автоматически.
- Тексты на главной — `app/templates/index.html`.
- Цвета/стили — `app/static/css/style.css`.
- Контакты поддержки (Telegram и email) — не захардкожены в шаблонах.
  Пока переменные не заданы, футер и виджет поддержки честно ничего не
  показывают вместо выдуманных `@your_telegram` / `hello@example.com`.
  Впишите реальные контакты в `.env`:

  ```
  SUPPORT_TELEGRAM_URL=https://t.me/ваш_юзернейм
  SUPPORT_EMAIL=you@example.com
  ```

## Способ оплаты «Криптовалюта»

В окне заказа есть вариант оплаты криптовалютой. Адрес кошелька **не
захардкожен** — специально, чтобы на сайте никогда не показывался
случайный/несуществующий адрес: если бы позже это случайно ушло в прод,
кто-то мог бы отправить туда настоящие деньги без возможности их вернуть.

Когда будет готов реальный адрес — добавьте его в `.env`:

```
CRYPTO_WALLET_ADDRESS=ваш_адрес_кошелька
```

и перезапустите сервер (или добавьте переменную в Environment на Render).
Пока переменная не задана, вместо адреса показывается пометка «адрес ещё
не подключён».

## Как сейчас устроена выдача сервера и почему

Реальной автоматизации (подключения к VPS/панели вроде Pterodactyl) пока
нет — настройка сервера происходит вручную. Поэтому кнопки в личном
кабинете «Перезагрузить» / «Продлить» / «Сменить тариф» не дёргают
никакую инфраструктуру напрямую — они создают заявку в `action_requests`,
которая появляется в админке (`/admin`), и администратор выполняет
действие руками и отмечает его выполненным. Это осознанный шаг: как
только выберете конкретного VPS-провайдера или панель управления —
можно будет подключить их API и заменить ручное выполнение части заявок
на автоматическое, не меняя интерфейс личного кабинета.

## Оплата

Принимать платежи картой в РФ можно только через платёжного оператора
(ЮKassa, CloudPayments и т.п.), а они требуют оформленный статус —
самозанятый, ИП или ООО. Без этого статуса подключить приём платежей
нельзя, поэтому сейчас заявка после оформления получает статус
«Ожидает оплаты», а оплату администратор подтверждает вручную (например,
переводом) и меняет статус на «Активен» в админке.

Самый быстрый способ оформить статус — зарегистрироваться самозанятым
через приложение «Мой налог» (обычно занимает один день, без визитов в
налоговую). После этого можно подключить ЮKassa — она явно поддерживает
приём платежей для самозанятых. Когда будете готовы — это отдельная
небольшая задача (добавить кнопку оплаты, которая ведёт на страницу
оплаты ЮKassa, и обработчик уведомления об оплате), архитектуру сайта
она не затронет.

## Деплой на Render.com

1. Залейте этот проект в свой репозиторий на GitHub.
2. На render.com: **New → Web Service**, подключите репозиторий.
3. Build command: `pip install -r requirements.txt`
4. Start command: `gunicorn run:app` (уже указано в `Procfile`, Render подхватит сам)
5. В разделе Environment добавьте переменные:
   - `SECRET_KEY` — `python -c "import secrets; print(secrets.token_hex(32))"`
   - `ADMIN_PASSWORD_HASH` — вывод `python generate_admin_hash.py`
6. Deploy. Render выдаст публичный адрес вида `https://your-app.onrender.com`.

**Важно про базу данных:** на бесплатном плане Render диск не постоянный —
при каждом передеплое или перезапуске сервиса файл `instance/shop.sqlite3`
(и заявки в нём) обнуляется. Для лендинга на старте это не критично, но
если заявки должны накапливаться надёжно — потребуется platform disk
(платный план) или переезд на управляемую БД (например, бесплатный
Postgres от Render). Скажите, когда это станет актуально — подключим.

Когда появится нагрузка или понадобится автоматизация — переезд на свой
VPS (gunicorn + nginx) не потребует переписывать приложение.

## Домен

Покупка домена — действие с вашими деньгами и аккаунтом, его нужно
сделать самостоятельно:

1. Выберите регистратора: для зоны `.ru`/`.рф` — reg.ru или nic.ru; для
   `.com`/`.dev`/др. — Namecheap или Cloudflare Registrar (обычно дешевле
   и без скрытых допкомиссий за продление).
2. Проверьте свободно ли желаемое имя и купите домен на выбранном
   регистраторе (нужны только ваши паспортные/контактные данные и оплата
   на их сайте).
3. В Render: откройте ваш Web Service → **Settings → Custom Domain** →
   добавьте купленный домен. Render покажет, какую DNS-запись создать
   (обычно `CNAME` на поддомене или `A`-запись для корневого домена).
4. Добавьте эту запись в панели регистратора (раздел DNS/управление
   записями) — привязка обычно применяется от нескольких минут до
   пары часов.
